Building plugins with JIB.Sdk

Third-party plugins are authored against JIB.Sdk, the single shared contract for device-host plugins. A plugin publishes settings, catalogs, control states, and health that the Configurator renders automatically.

Overview

JIB loads plugins from Plugins/ at host startup. Ten built-in plugins ship with the host, and external plugins can be dropped in the same way. Referencing JIB.Sdk is the only requirement; the Configurator needs no plugin-specific code.

Every plugin gets, for free:

  • typed settings with auto-generated editors in the Configurator;
  • health monitoring (10 s interval, auto-disable after 5 consecutive failures);
  • enable/disable per plugin from the Configurator;
  • display metadata via the [JibPlugin] attribute.

Authoring modes

SDK-only

A parameterless-constructor plugin that only references JIB.Sdk. Portable and suitable for third-party distribution.

Internal host

A plugin whose constructor receives DeviceHostPluginServices, giving full access to the RuntimeProviderChangeTracker, transports, and host services. Reserved for plugins shipped with the host.

Key SDK concepts

  • IDeviceHostPlugin / DeviceHostPluginBase — the base plugin contract.
  • RuntimeProviderChangeTracker — push live state updates (catalog changes, control states) to the host and Configurator.
  • [JibPlugin] — display metadata (name, description, version).
  • Typed settings — TextBox, Toggle, NumberBox, ComboBox, Endpoint; the Configurator builds the editor.
  • Static vs. dynamic catalogs — choose based on whether functions are known at compile time.
  • Health monitoring — automatic, with a configurable disable threshold.

Publishing assignable functions

For a function to appear in the Display palette, its RuntimeFunctionDescriptor must publish an explicit FunctionKind — in practice Telemetry or HostIntegration. Without it the function stays Unknown and is filtered out of the assignable list.

Actions can publish a recommended dispatch mode and the modes they support through the integration metadata, so the action card shows a correct Execution selector:

{
  "recommendedDispatchMode": "PulseOnly",
  "supportedDispatchModes": ["PulseOnly", "PressRelease"]
}

IPC protocol

The Configurator and the SimHub plugin talk to the host over TCP with JSON, and there is no shared DLL between them. The full protocol — wire format, message types, discovery, and the envelope — is documented in the repository:

Read IPC-Protocol.md

For an external plugin that needs to reach the host over TCP, follow the SimHub plugin pattern: raw TCP client, handshake plus heartbeat, zero reference to JIB.Sdk, and JSON built or parsed manually.
